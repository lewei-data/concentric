# 数字员工静态素材 · 客户端接入说明

适用版本：`mcp-asr 2.2.0`，mcp-bridge 静态挂载（2026-11-10 上线）
读者：Android / iOS / Web 客户端开发
关联文档：`README.md` 第 12 章（数字员工档案）、第 13 章（profile 接口）

---

## 1. 一句话结论

`profile` 返回的素材地址已经是**站点相对路径**，客户端只需拼上 MCP 同源域名：

```
https://ai.boraydata.com + /conring/asr/assets/avatars/ceo.png
= https://ai.boraydata.com/conring/asr/assets/avatars/ceo.png
```

- 不用 Token、不用 VPN、不用 8848 端口。
- 图片、视频都支持 `Range`（视频可拖动/边下边播）。
- 加/换素材后**立即生效**，无需重启服务、无需改客户端。

## 2. 地址从哪来

| 来源 | 值 |
| --- | --- |
| MCP 端点 | `https://ai.boraydata.com/conring/asr/mcp` |
| 服务端环境变量 | `ASR_ASSET_URL_BASE=/conring/asr/assets` |
| `profile` 返回 | `"asset_url_base": "/conring/asr/assets"` |
| 素材物理目录（服务端） | `/home/boray/opc-workbench/prototype/assets` |
| 对外 URL 前缀 | `https://ai.boraydata.com/conring/asr/assets/` |

链路：

```
[App] GET https://ai.boraydata.com/conring/asr/assets/avatars/ceo.png
  → nginx (192.168.31.208) location /conring/asr/   （整段反代，不再额外鉴权）
  → http://192.168.31.206:9102/assets/avatars/ceo.png
  → mcp-bridge --static-dir  .../prototype/assets  （StaticFiles，Starlette）
  → 文件字节
```

> 端点前缀是 `/conring/asr/`，后面**可以**接 `/assets/...`；只把域名拼成根路径（`https://ai.boraydata.com/faces/ceo.png`）会命中网关鉴权层，返回 **401**，这是最容易踩的坑。

## 3. 返回字段与素材对应关系

`profile`（全部/单人）中每个员工的素材字段：

| 字段 | 含义 | 典型 URL | 建议用途 |
| --- | --- | --- | --- |

## 4. HTTP 行为（实测）

| 请求 | 结果 |
| --- | --- |
| `GET .../avatars/ceo.png` | `200`，`Content-Type: image/png`，`Content-Length: 354076`，带 `etag` / `last-modified` / `accept-ranges: bytes` |
| `GET .../videos/ceo.talk.mp4` | `200`，`Content-Type: video/mp4`，`Content-Length: 66075` |
| `Range: bytes=0-1023` 取 mp4 | `206`，1024 B |
| 带 `If-None-Match: <etag>` 重新请求 | `304`（客户端可据此做本地缓存校验） |
| 不存在的文件名 | `404` |
| 把地址拼成 `https://ai.boraydata.com/avatars/ceo.png` | `401`（网关鉴权，**路径错**） |
| 无鉴权 | 不需要 `Authorization`，不要带 Bearer |

服务端**未设置 `Cache-Control`**，缓存策略由客户端决定：建议本地磁盘缓存 + `etag`/`last-modified` 条件请求（命中 `304` 就不重复下载）。

素材体积参考（实测）：头像 130–354 KB，面部特写约 133 KB，说话视频约 66 KB，待机视频约 66 KB。18 人全量头像约 6 MB，弱网建议按需加载。

## 5. Android 接入示例（纯 framework，可直接用）

### 5.1 拼 URL + 本地缓存 + 条件请求

（示例省略 imports：`java.io.*`、`java.net.HttpURLConnection`、`java.net.URL`；JSON 解析用 Android 自带的 `org.json`。）

```java
private static final String ASSET_BASE = "https://ai.boraydata.com";

static String assetUrl(String relative) {
    if (relative == null || relative.isEmpty()) return null;
    if (relative.startsWith("http://") || relative.startsWith("https://")) return relative;
    return ASSET_BASE + (relative.startsWith("/") ? relative : "/" + relative);
}

// etag 以文件形式存在缓存目录，命中 304 时复用本地图片
File fetchAsset(Context ctx, String relativeUrl, String cacheName) throws IOException {
    File dir = new File(ctx.getCacheDir(), "assets");
    if (!dir.exists()) dir.mkdirs();
    File out = new File(dir, cacheName);
    File etagFile = new File(dir, cacheName + ".etag");

    HttpURLConnection c = (HttpURLConnection) new URL(assetUrl(relativeUrl)).openConnection();
    c.setConnectTimeout(8000);
    c.setReadTimeout(20000);
    if (out.exists() && etagFile.exists()) {
        c.setRequestProperty("If-None-Match", readText(etagFile).trim());
    }
    int code = c.getResponseCode();
    if (code == HttpURLConnection.HTTP_NOT_MODIFIED) return out;      // 304，直接用缓存
    if (code != HttpURLConnection.HTTP_OK) throw new IOException("HTTP " + code);

    String etag = c.getHeaderField("ETag");
    File tmp = new File(dir, cacheName + ".tmp");
    try (InputStream in = c.getInputStream(); OutputStream os = new FileOutputStream(tmp)) {
        byte[] buf = new byte[16 * 1024];
        int n;
        while ((n = in.read(buf)) > 0) os.write(buf, 0, n);
    }
    if (!tmp.renameTo(out)) throw new IOException("rename failed");
    if (etag != null) writeText(etagFile, etag);
    return out;
}

static String readText(File f) throws IOException {
    byte[] b = new byte[(int) f.length()];
    try (FileInputStream in = new FileInputStream(f)) {
        int off = 0, n;
        while (off < b.length && (n = in.read(b, off, b.length - off)) > 0) off += n;
    }
    return new String(b, "UTF-8");
}

static void writeText(File f, String s) throws IOException {
    try (FileOutputStream out = new FileOutputStream(f)) { out.write(s.getBytes("UTF-8")); }
}
```

### 5.2 加载到界面

```java
// photo / face_url：直接 BitmapFactory.decodeFile；大图先按目标尺寸 inSampleSize 缩放
Bitmap bmp = BitmapFactory.decodeFile(fetchAsset(ctx, emp.optString("photo"), empId + ".png").getPath());

// videoTalk：优先用系统播放器（本地文件或直连 URL 都支持 Range）
VideoView vv = findViewById(R.id.avatarVideo);
vv.setVideoURI(Uri.parse(assetUrl(emp.optString("videoTalk"))));
vv.setOnPreparedListener(mp -> { mp.setLooping(true); vv.start(); });
```

> 播放器直连 URL 时，`MediaPlayer`/`ExoPlayer` 会自动发 `Range` 请求；若自行下载，建议先落盘再播，避免弱网卡顿。

### 5.3 回退顺序（与服务端 `mode` 判定保持一致）

```
videoTalk 存在 && 带宽 ≥ 600 kbps  → 视频播报
否则 videoIdle 存在                 → 待机视频 + 音频包络驱动动作
否则 photo 存在                     → 照片 + WAV 包络做口型/表情
否则                                → 纯语音（内置 Canvas 头像）
```

`has_photo=false` / `has_video=false` 时不要构造 URL，直接走下一级回退；`404` 也按「素材缺失」处理，不要弹错误。

## 6. 与服务端其它接口的配合

- `profile` 参数 `include_assets=false` 可只取档案文字（响应更小，适合列表页）；进详情页/播报前再按 `id` 拉一次带素材的档案。
- `voice_avatars` 专门列素材：返回 `{asset_dirs, asset_url_base, count, avatars:[{id,name,role,photo,videos,has_video}]}`，适合做「数字员工画廊」。
- 播报模式由 `voice_chat` 的 `mode`（`auto|voice|avatar|video`）与 `bandwidth_kbps` 决定，返回的 `avatar` 字段已经给出可用素材，客户端按第 5.3 节渲染即可。

## 7. 排查速查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `401` + `Bearer realm="sefs-mcp"` | 拼成了域名根路径（丢了 `/conring/asr/assets`） | 用 `asset_url_base` 原样拼，不要自己截断路径 |
| `404` | 文件名/id 不存在，或漏了 `/assets` | 对照 `missing_photo` / `missing_video`；路径必须是 `/conring/asr/assets/{avatars|faces|videos}/<id>.*` |
| `403`/`401` 只在部分网络出现 | 客户端替换了 Host 或走了别的反代 | 固定用 `https://ai.boraydata.com`，不要换成内网 `31.208` 的 https（证书 CN 不匹配） |
| 视频不能拖动 | 客户端整段下载后播放 | 直连 URL 播放，或自己实现 `Range` |
| 图片换了但客户端还是旧的 | 用了本地缓存且未校验 | 发 `If-None-Match`，或素材更新后清一次缓存 |
| 想要内网调试 | 内网可直连 | `http://192.168.31.206:9102/assets/...`（需 VPN），**仅调试用** |

## 8. 运维与安全须知

- 新增/替换素材：把文件丢进对应目录即可（`avatars/`、`faces/`、`videos/`），无需重启；文件名 = 员工 id。
- 静态目录由 `mcp-asr-http.service` 的启动参数挂载：
  `--static-dir /home/boray/opc-workbench/prototype/assets --static-path /assets`
  环境变量 `ASR_ASSET_URL_BASE` 决定返回 URL 前缀，两者必须成对修改。
- **素材当前公网无鉴权可读**（形象图/视频本身不是机密）。若后续放入敏感素材，应在 nginx 层加 token 或签名 URL，并同步改 `ASR_ASSET_URL_BASE`。
- 工作台 8848 端口只用于局域网预览，公网不暴露；客户端**不要**再指向 8848。

## 10. 自我介绍视频（服务端生成 · 客户端边下边播）

### 10.1 它是什么

每个员工的自我介绍视频由**服务端生成**，不是客户端录的：

```
员工档案字段（姓名/部门/职位/职责/技能…）
  → Hermes 大模型润色成 2~3 句口语（≤140 字）
  → TTS（CosyVoice2，用员工自己的音色）→ wav
  → ffmpeg：画面取 videos/<id>.talk.mp4 循环（没有则用照片 + 缓慢推镜），
            音轨取 TTS wav，输出 720×960 / 25fps / H.264+AAC / +faststart 的 MP4
  → assets/intro/<id>.mp4（同时落 <id>.txt 文案、<id>.json 元数据）
```

产出物走同一套静态通路：`/conring/asr/assets/intro/<id>.mp4`。

- **首次请求按需生成，之后复用缓存**——生成是耗时操作（本机实测 CEO 约 95 秒、PM 约 110 秒，TTS 占大头），不要在拉起档案页时同步等。
- MP4 带 `+faststart`（moov 前置）且支持 `Range`，客户端**直连 URL 播放即可边下边播**，不需要先整段下载，也不需要转 HLS。

### 10.2 生成 / 重建（服务端运维或首次预热）

```json
{"name":"intro_video","arguments":{"id":"ceo"}}                    // 单人生成，等完成再返回
{"name":"intro_video","arguments":{"wait":false}}                  // 18 人排队后台生成，立即返回
{"name":"intro_video","arguments":{"id":"ceo","force":true}}       // 忽略缓存重做（档案改了就重跑）
```

返回：

```json
{"count": 1,
 "dir": "/home/boray/opc-workbench/prototype/assets/intro",
 "url_base": "/conring/asr/assets",
 "items": [{"id": "ceo", "name": "陆清安", "ready": true, "cached": false,
            "video": "/conring/asr/assets/intro/ceo.mp4",
            "text": "大家好，我是陆清安，公司管理层的CEO……",
            "duration": 21.16, "size": 660258,
            "source": "video:ceo.talk.mp4", "generate_ms": 94762}],
 "failed": []}
```

`wait=false` 时返回 `{"count":18,"queued":true,"items":[{"id":"boss","queued":true,"ready":false}, …]}`，`ready` 表示该人当前是否已有可用视频（服务重启会中断排队，需重新触发）。

### 10.3 客户端：怎么知道有没有、怎么播

只看 `profile` 的三个字段，不要猜文件是否存在：

```java
JSONObject emp = ...;
boolean ready = emp.optBoolean("introReady");
String  url   = emp.optString("introVideo", "");        // 站点相对路径
double  dur   = emp.optDouble("introDuration", 0);      // 服务端实测时长（秒）
String  text  = emp.optString("introText", "");         // 字幕 / 无网兜底朗读
if (!ready || url.isEmpty()) { showEmptyState(); return; }   // 不构造 URL，避免 404
```

播放（纯 framework，直连 URL 边下边播）：

```java
VideoView vv = findViewById(R.id.introVideo);
vv.setVideoURI(Uri.parse(assetUrl(emp.optString("introVideo"))));   // assetUrl 见 5.1
vv.setOnPreparedListener(mp -> {
    mp.setLooping(false);          // 自我介绍播一遍即可
    vv.start();
});
vv.setOnErrorListener((mp, what, extra) -> { showFallbackText(emp.optString("introText")); return true; });
```

- 想要「秒开」：先用 5.1 的 `fetchAsset` 把 mp4 落到缓存再播（体积约 0.5–0.7 MB），代价是首次要下完。
- `introVideo` 是相对路径，**必须**拼 `/conring/asr/assets` 前缀，拼成 `https://ai.boraydata.com/intro/ceo.mp4` 会 401。
- 服务端没有 JSON/ETag 变化通知：档案页进入时重新调一次 `profile`（或 `profile {"id":"ceo"}`）拿最新 `introReady`。

## 11. 实时通话（HLS 直播 · 音视频同流）

### 11.1 方案与结论

客户端在员工档案页点「通话」，服务端起一路 **HLS 直播**：员工画面（`talk.mp4` 循环，没有则照片）作为视频源，**命名管道实时写入语音 PCM** 作为音频源，ffmpeg 边推边切成 1 秒分片，滚动更新 `index.m3u8`。

- 音视频在同一条流里复用（H.264 + AAC，统一时间戳）→ **语音与画面天然同步**，客户端不需要自己做对齐。
- 客户端 `MediaPlayer` / `VideoView` 系统原生支持 HLS，**零第三方依赖**（不上 WebRTC、不引 ExoPlayer）。
- 分片 1 秒 + 播放器缓冲，端到端延迟量级 **2–4 秒**（1 s 分片 × 2~3 个缓冲；未做低延迟 HLS 扩展，属正常范围）。

### 11.2 接口：`live_call`

| action | 参数 | 返回 |
| --- | --- | --- |
| `start`（默认） | `avatar_id`（默认 `ceo`）、`first_segment_sec`（等首个分片，默认 8）、可选 `text`（起流即说一句） | `session_id`、`hls_url`、`hls_url_full`、`ready`、`segment_sec`、`status`、`speech_seconds`、`segments`、`sync` |
| `say` | `session_id` + `text`（服务端 TTS，音色/情绪取员工档案）或 `audio_base64`/`audio_path`；可覆盖 `voice`/`emotion` | 同上 + `queued_seconds` |
| `stop` | `session_id` | 同上，`status=ended`，播放列表补 `#EXT-X-ENDLIST` |
| `status` | `session_id` | 同上（`status` 为 `live` / `ended`） |

```json
// 1) 发起
{"name":"live_call","arguments":{"action":"start","avatar_id":"ceo"}}
→ {"session_id":"lv_4dd8b342","status":"live","avatar_id":"ceo",
```

### 11.3 接通问候与空闲提醒（2026-11-10）

为避免「接通后没声音、以为没连上」，服务端在 `start` 时就先把一句问候混进流里，客户端不用做任何事：

| 时机 | 行为 | 实测 |
| --- | --- | --- |
| 刚接通 | 说「老板你好，我在。」，落在 `seg_00000~00001`，播放器起播即有声音 | `start` 2.3s 返回，`speech_seconds=2.0`，首片 9588 B |
| 连续 45s 没说过话 | 主动说「老板，我在呢。」 | 第 44~45 分片出现 5076/9964 B，`speech_seconds` 2.0→3.39 |

- 问候语预合成后缓存，命中时立刻混入；TTS 未就绪时后台补合成，晚几秒补进流里（不会静默到底）。
- 可配置：`ASR_GREETING_TEXTS`（`|` 分隔，第一句＝接通问候，最后一句＝空闲提醒）、`ASR_IDLE_NUDGE_SEC`（默认 45，<=0 关闭）。

### 11.4 语音响度归一化（2026-11-10）

不同音色、不同长度的 TTS 句子原始音量不一致，手机外放会「一句响一句小」。服务端在**混入直播流之前**统一做一次响度处理，客户端无需改动：

```
TTS wav → ffmpeg loudnorm 测一遍（print_format=json）
        → loudnorm 线性第二遍（I=-16 LUFS / TP=-1.5 dBTP，整句等比缩放，不做逐段压缩）
        → volume=+3dB
        → alimiter（限幅 -1 dBFS，防削波）
        → s16le / 24000 / mono → FIFO → HLS
```

| 项 | 值 |
| --- | --- |
| 目标响度 | `-16 LUFS`（`ASR_LOUDNESS_I`） |
| 目标真峰值 | `-1.5 dBTP`（`ASR_LOUDNESS_TP`） |
| 附加增益 | `+3 dB`（`ASR_LIVE_GAIN_DB`） |
| 限幅 | `alimiter limit=0.891`（= -1 dBFS） |
| 开关 | `ASR_LIVE_LOUDNORM=0` 关闭，退回原始音量 |

实测（本机，同一份 `老板你好，我在。` wav 走服务端真实代码路径）：

| 阶段 | 响度 |
| --- | --- |
| TTS 原始 | `-15.37 LUFS` / `0.01 dBTP` |
| 服务端输出 | `-14.73 LUFS` / `-1.00 dBTP` |

> 说明：TTS 源本身已在 -16~-17 LUFS、峰值顶到 0 dBFS，所以归一化的主要价值是**跨句一致性 + 防削波**，纯响度提升约 +1.3 LU。若现场仍觉偏小，调 `ASR_LIVE_GAIN_DB=5`（实测 `-14.10 LUFS`）即可，不用改代码。
> 极短句/静音句可能量不出响度，此时跳过 loudnorm 但仍走 `+3 dB + 限幅`，不会丢句。

### 11.5 空闲工作简报（2026-11-10）

老板接通后一直不下新指令，不能只反复说「我在」。空闲满阈值后，服务端把当前任务/状态压成一句话念出来：

```
接通 → 10s 无新指令 → 「老板，我在呢。」（确认在线，之后每 60s 最多重提一次）
     → 90s 无新指令 → 工作简报（本次通话只播一次，之后恢复普通提醒）
```

简报**只读本地快照，不调大模型**（agent 一轮要 2~5 分钟，等不起）：

| 来源 | 取什么 |
| --- | --- |
| `动态/runtime.json` | `stats.traces/published/blockedPublish`、待拍板审批数、高风险数、最新风险单标题 + 结论 |
| `动态/事件流.md` | `escalation` 行按内容去重计数（升级给老板的事项） |
| `OPC/交付物/*/06-log.md` | 最近一天有更新的交付物数 |
| `runtime.json` 的 `savedAt` | 快照超过 2 小时会在语音里明说「快照是 N 小时前的」 |

真实产出（本机 2026-11-10，111 字 / 约 20 秒语音）：

> 老板，没新指令，我报下进度：跑了 27 条任务链路，已发布 0、阻断 1；1 项待您拍板，其中 1 项高风险；最新问题是跨项目人设串味，检测到狗大人稿件使用文人莫克人设与素材。（快照是 14 小时前的）要细说哪块，您吩咐。

| 项 | 实测值 |
| --- | --- |
| 文本生成耗时 | `0.004 s`（纯本地读文件） |
| TTS 合成 | 122 字版本 `39.2 s`，音频 `22.0 s`，RTF `1.77` |
| 预生成时机 | `start` 后立即后台合成，空闲触发时直接入流，不现场等 TTS |
| 长度上限 | 默认 120 字；超长时整段丢弃末尾事项（交付物 → 升级 → 风险），不会念出半句 |
| 合成超时 | `ASR_BRIEFING_TTS_TIMEOUT=240 s`（独立于「收到」的 90 s） |

`status` 返回新增 `briefing_ready`（布尔）：`true` 表示简报语音已备好，空闲触发即可播。

环境变量：`ASR_BRIEFING=0` 关闭、`ASR_BRIEFING_SEC=90` 触发阈值、`ASR_BRIEFING_MAX_CHARS=120`、`ASR_BRIEFING_DIR=/opt/sefs/obsidian`、`ASR_BRIEFING_TTS_TIMEOUT=240`。

空闲提醒本身由 `ASR_IDLE_NUDGE_SEC`（默认 `10`）控制首句触发时间，`ASR_IDLE_NUDGE_REPEAT_SEC`（默认 `60`）控制重复间隔——只改前者会把提醒变成每 10 秒刷屏。

> 为什么简报要单独给 240 s：服务刚重启时 TTS 池（6 进程）前面还排着约 12 条「收到/问候」预热（约 80~90 s），
> 简报本身 30 s 左右。2026-11-10 18:47 就出现过「简报已经合成完（TTS 日志 33 s 完成），但客户端按 90 s 判超时丢弃」，
> 结果 `briefing_ready` 一直是 `false`、空闲时只念「我在呢」。超时放在后台线程里，不影响通话，给足即可。
> 若触发时刻简报还没合成完，会先念普通提醒，等简报就绪后的下一轮再念，不会丢。

> 空闲判定用「老板最后一次下指令的时间」（`voice_chat` 带 `live_session` 时刷新），不是「最后一次出声」——否则每句问候都会把计时清零，简报永远轮不到。

### 11.6 客户端播放

```java
// 1) 起流
JSONObject r = mcp.call("live_call", json("action","start","avatar_id",empId));
String sid = r.getString("session_id");
String hls = r.optString("hls_url_full", assetUrl(r.getString("hls_url"))); // 优先绝对地址

// 2) 播放（系统 MediaPlayer / VideoView，原生 HLS）
VideoView vv = findViewById(R.id.liveVideo);
vv.setVideoURI(Uri.parse(hls));
vv.setOnPreparedListener(mp -> { mp.setLooping(false); vv.start(); });
vv.setOnErrorListener((mp, what, extra) -> { retryWithStatus(sid); return true; });

// 3) 说话（优先把 voice_chat 返回的 wav 直接混进流，省掉 TTS 等待）
mcp.call("live_call", json("action","say","session_id",sid,"audio_base64",replyWavBase64));

// 4) 挂断
mcp.call("live_call", json("action","stop","session_id",sid));
```

播放要点：

- **`ready=false` 时先别播**（首个分片还没落盘），等 1–2 秒重试或再调 `status`；`start` 默认已经等到播放列表出现才返回。
- 播放列表是 `event` 型且 `hls_list_size 0`（不丢旧分片），**通话越长 m3u8 越长**；系统播放器会持续重载列表，无需客户端处理。
- `m3u8` 与 `.ts` 响应头是 `Cache-Control: no-cache, no-store, must-revalidate`，**客户端不要缓存**这两个文件，否则一直停在同一帧。
- `stop` 后播放列表以 `#EXT-X-ENDLIST` 收尾，播放器会正常结束而不是无限转圈；已播内容在 `LIVE_TTL`（默认 900 秒）内还可回看，之后目录被自动清理。
- 并发上限 `ASR_LIVE_SESSIONS_MAX`（默认 8），满了 `start` 直接报错，需先 `stop` 旧会话。

### 11.7 和 `voice_chat` 联动（推荐用法）

实时通话中让员工「听到并回答」，用 `voice_chat` 的 `live_session` 参数把回复语音直接混进同一路流：

```json
{"name":"voice_chat","arguments":{"audio_base64":"<麦克风 16k WAV>","live_session":"lv_4dd8b342"}}
```

服务端行为：识别 → 「收到」语音先混入流 → agent 跑完 → 正式回复再混入同一路流；返回的 `payload.live` 里是可读的 `session_id` / `hls_url` / `speech_seconds`。

> ⚠️ 此时**客户端只播 `hls_url`，不要再播返回的 audio 块**，否则同一句话会响两遍（流里一遍、本地一遍）。

### 11.8 排查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `start` 报「没有可用的画面素材」 | 该员工既无 talk/idle 视频也无照片 | 先补素材；`profile` 里 `has_video/has_photo` 都是 false |
| `ready=false` / 播放器报 404 | 起流后立刻播，首个分片未生成 | 等 1–2 s 重试，或把 `first_segment_sec` 调大 |
| 有画面没声音 | 客户端没触发 `say`；从 `start` 到第一次 `say` 之间流里是静音 | 正常现象；`speech_seconds` 会随之增长 |
| `say` 后要等十几秒才有声音 | `text` 走服务端 TTS（CosyVoice2 首次合成较慢） | 传 `audio_base64`（用已有 wav）可立即入流 |
| 画面卡住/停在第一帧 | 中间层缓存了 m3u8 或 ts | 确认响应头是 no-store；客户端不要缓存这两个后缀 |
| `会话不存在或已过期` | 会话被 `stop` 超过 TTL，或服务重启 | 重新 `start` 拿新 `session_id` |
| 声音重复 | `voice_chat(live_session=…)` 后客户端又播了 audio 块 | 只播 HLS |

### 12.2 时序

```
点「通话」
  ├─ live_call{action:start, mode:audio, avatar_id:secretary}
  │     → session_id / hls_url / ready / mode=audio
  ├─ MediaPlayer.setDataSource(hls_url) → 循环播放（后续分片自动追加）
  ├─ AudioRecord 16k/mono 连续采集 ── 本地能量断句（静音 0.7 s 收尾）
  │     └─ 每句 → voice_chat{audio_base64, live_session:session_id}
  │           服务端：ASR → 「收到」混入流 → agent → 正式回复混入流
  └─ 再点（红色）→ live_call{action:stop} + 停止采集/播放
```

> 同一时刻只允许一路通话；`voice_chat` 一次可能要十几秒到几分钟，客户端用**单线程队列**按顺序发送，避免两句话的回复交叉。

### 12.4 新增 `RealtimeVoiceCall.java`

放在 `app/src/main/java/com/boray/voicemcp/RealtimeVoiceCall.java`。假设工程已有 `McpClient.call(String tool, JSONObject args)`（返回工具 `result` 的 JSONObject）和 `McpConfig.DEFAULT_URL`；若签名不同，只改 `call()` 两处。

```java
package com.boray.voicemcp;

import android.media.AudioAttributes;
import android.media.AudioFormat;
import android.media.AudioRecord;
import android.media.MediaPlayer;
import android.media.MediaRecorder;
import android.os.Handler;
import android.os.Looper;
import android.util.Base64;

import org.json.JSONObject;

import java.io.ByteArrayOutputStream;
import java.util.concurrent.ExecutorService;
import java.util.concurrent.Executors;
import java.util.concurrent.atomic.AtomicBoolean;

/**
 * 首页实时语音通话：live_call(mode=audio) 起一路 HLS 音频流，
 * 麦克风连续采集 + 能量断句，每句走 voice_chat(live_session) 把回复混进同一路流。
 */
public final class RealtimeVoiceCall {

    public static final int IDLE = 0, CONNECTING = 1, LIVE = 2, ENDED = 3, ERROR = 4;

    public interface Listener {
        void onState(int state, String message);      // 切按钮文案/红色态
        void onLine(boolean fromUser, String text);   // 实时转写与回复文字
        void onLevel(float level);                    // 0~1，可选做波形
    }

    private static final int SAMPLE_RATE = 16000;
    private static final float SPEECH_RMS = 0.018f;   // 约 -35 dBFS，低于它算静音
    private static final int SILENCE_MS = 700;        // 说完多久收一句
    private static final int MAX_UTTERANCE_MS = 15000;

    private final McpClient mcp;
    private final String origin;                      // https://ai.boraydata.com
    private final Listener listener;
    private final ExecutorService net = Executors.newSingleThreadExecutor();
    private final Handler ui = new Handler(Looper.getMainLooper());
    private final AtomicBoolean running = new AtomicBoolean(false);

    private volatile String sessionId;
    private volatile MediaPlayer player;
    private volatile Thread recordThread;
    private int retries;

    public RealtimeVoiceCall(McpClient mcp, String endpointUrl, Listener listener) {
        this.mcp = mcp;
        this.listener = listener;
        int i = endpointUrl.indexOf("/conring/");
        this.origin = i > 0 ? endpointUrl.substring(0, i) : endpointUrl;
    }

    public boolean isRunning() { return running.get(); }

    public void start(final String employeeId) {
        if (!running.compareAndSet(false, true)) return;
        retries = 0;
        emit(CONNECTING, "正在接通…");
        net.execute(() -> {
            try {
                JSONObject a = new JSONObject();
                a.put("action", "start");
                a.put("mode", "audio");                  // 纯语音，不出画面
                if (employeeId != null && !employeeId.isEmpty()) a.put("avatar_id", employeeId);
                JSONObject r = mcp.call("live_call", a);
                sessionId = r.getString("session_id");
                String hls = absolute(r.getString("hls_url"));
                ui.post(() -> play(hls));
                startRecorder();
                emit(LIVE, "通话中 · " + r.optString("avatar_id", employeeId));
            } catch (Exception e) {
                fail("接通失败：" + e.getMessage());
            }
        });
    }

    public void stop() {
        if (!running.getAndSet(false)) return;
        stopRecorder();
        ui.post(this::stopPlayer);
        final String sid = sessionId;
        sessionId = null;
        emit(ENDED, "通话已结束");
        if (sid != null) net.execute(() -> {
            try {
                JSONObject a = new JSONObject();
                a.put("action", "stop");
                a.put("session_id", sid);
                mcp.call("live_call", a);
            } catch (Exception ignored) { }
        });
    }

    // ---------------------------------------------------------------- 播放
    private void play(String url) {
        if (!running.get()) return;
        stopPlayer();
        MediaPlayer mp = new MediaPlayer();
        player = mp;
        mp.setAudioAttributes(new AudioAttributes.Builder()
                .setUsage(AudioAttributes.USAGE_MEDIA)
                .setContentType(AudioAttributes.CONTENT_TYPE_SPEECH).build());
        try {
            mp.setDataSource(url);
            mp.setOnPreparedListener(m -> { if (running.get()) m.start(); });
            mp.setOnErrorListener((m, what, extra) -> {
                m.release();
                if (running.get() && retries++ < 2) ui.postDelayed(() -> play(url), 1500);
                return true;
            });
            mp.prepareAsync();
        } catch (Exception e) {
            fail("播放失败：" + e.getMessage());
        }
    }

    private void stopPlayer() {
        MediaPlayer mp = player;
        player = null;
        if (mp != null) {
            try { mp.stop(); } catch (Exception ignored) { }
            mp.release();
        }
    }

    // ---------------------------------------------------------------- 采集 + 断句
    private void startRecorder() {
        Thread t = new Thread(this::recordLoop, "voice-call-rec");
        recordThread = t;
        t.start();
    }

    private void stopRecorder() {
        Thread t = recordThread;
        recordThread = null;
        if (t != null) t.interrupt();
    }

    private void recordLoop() {
        int min = AudioRecord.getMinBufferSize(SAMPLE_RATE,
                AudioFormat.CHANNEL_IN_MONO, AudioFormat.ENCODING_PCM_16BIT);
        AudioRecord rec = new AudioRecord(MediaRecorder.AudioSource.VOICE_COMMUNICATION,
                SAMPLE_RATE, AudioFormat.CHANNEL_IN_MONO,
                AudioFormat.ENCODING_PCM_16BIT, Math.max(min * 2, 6400));
        if (rec.getState() != AudioRecord.STATE_INITIALIZED) {
            rec.release();
            fail("麦克风初始化失败，请检查录音权限");
            return;
        }
        short[] buf = new short[320];                 // 20 ms
        ByteArrayOutputStream utter = new ByteArrayOutputStream();
        boolean speaking = false;
        long speechStart = 0, lastVoice = 0;
        rec.startRecording();
        try {
            while (running.get()) {
                int n = rec.read(buf, 0, buf.length);
                if (n <= 0) continue;
                float rms = rms(buf, n);
                final float level = Math.min(1f, rms * 8f);
                ui.post(() -> listener.onLevel(level));
                long now = System.currentTimeMillis();
                if (rms >= SPEECH_RMS) {
                    if (!speaking) { speaking = true; speechStart = now; utter.reset(); }
                    lastVoice = now;
                    write(utter, buf, n);
                } else if (speaking) {
                    write(utter, buf, n);             // 句尾静音一并保留，听起来更自然
                    if (now - lastVoice >= SILENCE_MS || now - speechStart >= MAX_UTTERANCE_MS) {
                        speaking = false;
                        byte[] wav = wav(utter.toByteArray());
                        utter.reset();
                        if (wav.length > 44 + SAMPLE_RATE) send(wav);   // 至少 0.5 秒
                    }
                }
            }
        } finally {
            try { rec.stop(); } catch (Exception ignored) { }
            rec.release();
        }
    }

    private void send(byte[] wav) {
        if (!running.get() || sessionId == null) return;
        net.execute(() -> {
            try {
                JSONObject a = new JSONObject();
                a.put("audio_base64", Base64.encodeToString(wav, Base64.NO_WRAP));
                a.put("language", "zh");
                a.put("model", "small");
                a.put("live_session", sessionId);     // 回复直接混进通话流
                JSONObject r = mcp.call("voice_chat", a);
                JSONObject p = r.optJSONObject("payload");
                if (p == null) p = r;
                String q = p.optString("question", "");
                String ans = p.optString("answer", "");
                if (!q.isEmpty()) ui.post(() -> listener.onLine(true, q));
                if (!ans.isEmpty()) ui.post(() -> listener.onLine(false, ans));
            } catch (Exception e) {
                ui.post(() -> listener.onState(ERROR, "这一句没发出去，请再说一次"));
            }
        });
    }

    // ---------------------------------------------------------------- 工具
    private String absolute(String url) {
        return url.startsWith("http") ? url : origin + url;
    }

    private void fail(String msg) {
        running.set(false);
        stopRecorder();
        ui.post(() -> { stopPlayer(); listener.onState(ERROR, msg); });
    }

    private void emit(int state, String msg) {
        ui.post(() -> listener.onState(state, msg));
    }

    private static float rms(short[] buf, int n) {
        double sum = 0;
        for (int i = 0; i < n; i++) {
            double v = buf[i] / 32768.0;
            sum += v * v;
        }
        return (float) Math.sqrt(sum / Math.max(1, n));
    }

    private static void write(ByteArrayOutputStream out, short[] buf, int n) {
        for (int i = 0; i < n; i++) {
            int v = buf[i];
            out.write(v & 0xFF);
            out.write((v >> 8) & 0xFF);
        }
    }

    private static byte[] wav(byte[] pcm) {
        int size = pcm.length;
        byte[] h = new byte[44];
        writeInt(h, 0, 0x46464952);                   // RIFF
        writeInt(h, 4, 36 + size);
        writeInt(h, 8, 0x45564157);                   // WAVE
        writeInt(h, 12, 0x20746D66);                  // fmt
        writeInt(h, 16, 16);
        writeShort(h, 20, 1);                         // PCM
        writeShort(h, 22, 1);                         // mono
        writeInt(h, 24, SAMPLE_RATE);
        writeInt(h, 28, SAMPLE_RATE * 2);
        writeShort(h, 32, 2);
        writeShort(h, 34, 16);
        writeInt(h, 36, 0x61746164);                  // data
        writeInt(h, 40, size);
        byte[] out = new byte[44 + size];
        System.arraycopy(h, 0, out, 0, 44);
        System.arraycopy(pcm, 0, out, 44, size);
        return out;
    }

    private static void writeInt(byte[] b, int off, int v) {
        b[off] = (byte) v; b[off + 1] = (byte) (v >> 8);
        b[off + 2] = (byte) (v >> 16); b[off + 3] = (byte) (v >> 24);
    }

    private static void writeShort(byte[] b, int off, int v) {
        b[off] = (byte) v; b[off + 1] = (byte) (v >> 8);
    }
}
```

### 12.7 边界与排查

| 现象 | 原因 / 处理 |
| --- | --- |
| 点了没反应 | `live_call` 未部署或网关未重启：先 `tools/list` 看有没有 `live_call` |
| `start` 报「没有可用的画面素材」 | 说明没带 `mode=audio`；纯语音不需要素材 |
| 一直「正在接通…」 | 服务端等首个分片（默认 8 秒）；超时看 `ffmpeg.log`，或把 `first_segment_sec` 调小 |
| 接通要 10 秒以上 | `start` 里带了 `text` 问候语，会先等 TTS 合成；**通话不要传 `text`**，实测不带问候 2.2 秒接通 |
| 有画面没声音（video 模式） | 纯语音场景请确认 `mode=audio`，不要复用 `VideoView` |
| 回复慢 | `voice_chat` 要等 agent 执行完（十几秒~几分钟）；「收到」会先入流，属正常 |
| 连说两句回复交叉 | 客户端按单线程队列发送；v1 不支持打断，等上一句回复完再说 |
| 挂断后还在响 | 先 `player.stop()` 再 `live_call stop`；重新通话前 `release()` |
| 播放器几秒后停 | 中间层缓存了 m3u8/ts；确认响应头 `no-store`，客户端不要缓存 |
| 手机外放/听筒不对 | `AudioAttributes` 用 `USAGE_MEDIA`；若想听筒改 `USAGE_VOICE_COMMUNICATION` |
| 显示「接通」但整通没有一句语音 | 以前「收到」语音同步合成超过 8 秒就被丢弃（`speech_seconds=0`）。现已改为超时后后台补合成再混入，并预热常用 ack；**若仍为 0，先看服务端日志有没有「补混入」** |
| 听到的内容比说话晚一大截 | 纯语音列表以前是 `EVENT + hls_list_size 0`，播放器从第 0 片起播。现已改成 5 片滑动直播窗口，新接入约 2~3 秒延迟；客户端**不要缓存 m3u8** |
| 说完了但正式回答一直没来 | agent 任务常要 150~300 秒，比一次通话还长；任务完成时若已挂断，`live.ended=true` 且不会再有语音入流，客户端需用 `voice_job` 取回结果自己播 |

> 说明：第 12.4/12.5 的 Java 代码是按本工程「零第三方依赖 + `McpClient.call()`」的既有约定写的参考实现，**未在 Windows 工程里编译验证**（本机没有该工程源码）。粘贴后请先 `assembleDebug`，若 `McpClient.call()` 返回的是 MCP `result` 而不是工具 payload，把 `send()` 里的取字段改成先解析 `content[0].text` 再 `JSONObject`。

### 12.8 「显示接通但没声音」定位记录（2026-11-10 实测）

服务端流本身是好的：把已结束会话的 `index.m3u8` 整段解码，得到 90.05 秒连续音频，其中 21.0~24.5 秒有 3.5 秒人声。问题出在「语音进流太晚」和「超时把语音丢了」两处，均已修正。

| 环节 | 实测值 | 说明 |
| --- | --- | --- |
| `live_call start mode=audio` | 2.2 秒，播放列表 2 个分片 | 改完后固定等 2 个 `#EXTINF` 再返回，播放器不用面对空列表 |
| 直播列表 | 8 秒后 5 个分片、无 `#EXT-X-PLAYLIST-TYPE` | 滑动窗口，新接入从直播边缘起播 |
| TTS（CosyVoice2，本机 CPU） | RTF 1.7~6.4：2.26 秒语音要 6.1~16.2 秒；10.1 秒语音要 17.5~51.9 秒 | **这是对话延迟的主因**，也是 ack 常超时的原因 |
| ASR（whisper small，CPU） | 2.3 秒语音约 5 秒 | `voice_chat` 端到端 8.0 秒返回（含 ack） |
| ack 混入位置 | 通话第 9~11 秒（`seg_00016~00018`，4~10 KB） | ack 2.25 秒，命中预热缓存后是秒级 |
| 正式回复 | 任务 154.3 秒完成，通话只到 90.8 秒 | `live.ended=true`，回复无法再入流 |

对应的服务端改动（`/opt/sefs/opc-workbench/mcp-asr/server.py`）：

1. 纯语音 HLS 从 `EVENT + hls_list_size 0` 改为 5 片滑动直播窗口（不写 PLAYLIST-TYPE）。
2. `_live_start` 等到播放列表里出现 2 个分片再返回。
3. 新增 `_live_ack_later`：`ack_audio` 同步超时（默认 8 秒）不再丢语音，后台按 `ASR_ACK_TTS_LATE`（默认 90 秒）继续合成，好了直接补混进流。
4. `prewarm_acks` 按「小秘书 / ceo 的档案音色 + 情绪」预热常用「收到」，缓存 key 与 `voice_chat` 完全一致（以前预热的是无情绪版本，永远命不中）。
5. `_run_job` 给 `live` 增加 `ended` 字段，会话已挂断时日志会写明「本次语音未混入」。

> 仍存在的体验问题（服务端无法绕过）：agent 任务 150~300 秒，比一次通话还长。要真正「实时问答」，需要让 agent 先回一句短答或者支持流式输出，这属于 agent 侧改造，不在本次范围。

### 12.9 员工侧电平时间轴（服务端已实现，2026-11-10）

**问题**：首页音量条原来只读 `AudioRecord` 的麦克风 RMS，员工说话时不会跟着跳；`voice_chat` / `voice_job` 也不下发任何电平字段（服务端全文检索 `level / speech_level / audio_level / energy / volume` 均为 0 处命中）。

**契约**：`live_call start` 的返回里新增以下字段：

```json
{"level_url": "/conring/asr/assets/live/<session_id>/level.json",
 "level_url_full": "https://ai.boraydata.com/conring/asr/assets/live/<session_id>/level.json",
 "level_fps": 10, "level_window_sec": 120}
```

`level.json` 每 200 ms 原子重写一次（先写 `.tmp` 再 `os.replace`），内容是**与 HLS 同一条媒体时间轴**的滚动窗口：

```json
{"session_id":"lv_742062b5","seq":237,"fps":10,"t0":0.0,
 "lv":[0,0,0,12,38,61,90],"edge":48.7,"wall":1762761234.567,
 "elapsed":48.7,"status":"live"}
```

| 字段 | 含义 |
| --- | --- |
| `lv[i]` | 媒体时间 `t0 + i/fps` 这一格的员工侧电平，0~100（RMS 映射 -50~-6 dBFS，静音为 0） |
| `edge` | 已写进 HLS 管道的累计媒体秒数（直播边缘）；`t0 + len(lv)/fps` ≈ `edge` |
| `t0` | 窗口第一格的媒体时间；超过 120 秒窗口后大于 0 |
| `status` | `live` / `ended`（挂断后仍保留 `ASR_LIVE_TTL` 分钟内可回放） |

**客户端取电平（与听到的声音同步，不领先）**：

1. 起播时读一次 `index.m3u8`，取 `#EXT-X-MEDIA-SEQUENCE` 与 `#EXT-X-TARGETDURATION`，记 `mediaBase = MEDIA-SEQUENCE × TARGETDURATION`；
2. 之后每 100~200 ms：`mediaT = mediaBase + player.getCurrentPosition() / 1000.0`；
3. 从最近的 `level.json` 取 `idx = round((mediaT - t0) * fps)`，越界用最后一格，两格之间线性插值；
4. 音量条显示 `max(自己麦克风电平, 员工侧电平)`；`status=ended` 或 3 秒没拉到新 `seq` 时员工侧归零。

**为什么不放 `voice_chat` 回执里**：回执是一次性 JSON，只能带一个瞬时标量；HLS 播放比直播边缘晚 2~3 秒，标量会让画面领先声音，且长句超过 3 秒就归零。时间轴 + 媒体时间对齐才能同起同落。

**实测（2026-11-10，会话 `lv_742062b5`）**：

| 检查项 | 结果 |
| --- | --- |
| 静音阶段 | `max(lv)=0`、`nz=0`，`edge` 按 1 秒/秒递增 |
| 播报阶段（TTS 合成完成后入流） | `max(lv)=94`，非零格随语音增长 |
| 媒体轴一致性 | 挂断时 `edge=50.8`，目录内 `seg_*.ts` 共 51 个、每片 0.998 s |
| 静态通路 | `GET /assets/live/<sid>/level.json` 200 + `Cache-Control: no-store`；改前会因 `StaticFiles` 先 stat 后开文件读到半截 JSON（`IncompleteRead`），已在 `bridge.py` 改成整读快照 |

服务端开关：`ASR_LIVE_LEVEL=0` 关闭（默认开）、`ASR_LIVE_LEVEL_FPS`（默认 10）、`ASR_LIVE_LEVEL_WINDOW`（默认 120 秒）、`ASR_LIVE_LEVEL_FLUSH_SEC`（默认 0.2 秒）。

### 12.9.1 客户端参考实现（Android / Java，2026-11-10）

> 本机没有 Android 工程源码，**未在真机编译运行**。下面的换算逻辑与 12.9 的契约逐条对应，已用实测会话 `lv_742062b5` 的数据离线验算（见 12.9.2）。

`LiveLevelMeter`：单线程轮询 + `MediaPlayer.getCurrentPosition()` 换算，无第三方依赖（`HttpURLConnection` + `org.json`）。放在工程的任意包下即可。

```java
import android.media.MediaPlayer;
import android.os.Handler;
import android.os.Looper;

import org.json.JSONArray;
import org.json.JSONObject;

import java.io.ByteArrayOutputStream;
import java.io.InputStream;
import java.net.HttpURLConnection;
import java.net.URL;
import java.util.concurrent.ExecutorService;
import java.util.concurrent.Executors;

/**
 * 实时通话的员工侧电平：轮询 level.json，按「媒体时间」取格，和听到的声音同步。
 * 用法：MediaPlayer 起播后 start()，挂断/onDestroy 时 stop()。
 */
public class LiveLevelMeter {

    public interface Listener {
        /** 0~1，员工侧静音 / 已挂断 / 3 秒没有新快照时为 0 */
        void onLevel(float level01);
    }

    private static final long POLL_MS = 150;     // 服务端 200ms 重写一次，150ms 轮询足够
    private static final long STALE_MS = 3000;   // 3 秒没有新 seq 就归零
    private static final long SEEK_BACK_MS = 500; // 位置回跳超过 0.5s 视为播放器重载

    private final String levelUrl;
    private final String playlistUrl;
    private final MediaPlayer player;
    private final int fpsHint;
    private final float segHint;
    private final Handler main = new Handler(Looper.getMainLooper());
    private final ExecutorService io = Executors.newSingleThreadExecutor();

    private volatile Listener listener;
    private volatile boolean running;

    private volatile float[] lv = new float[0];
    private volatile float t0 = 0f;
    private volatile float fps = 10f;
    private volatile float edge = 0f;
    private volatile String status = "live";
    private volatile int lastSeq = -1;
    private volatile long lastSeqAt = 0L;

    /** 播放位置 0 对应的媒体时间（起播那一刻播放列表首片的起始时间） */
    private volatile float anchorMedia = 0f;
    private volatile long lastPosMs = -1L;

    /**
     * @param levelUrl    live_call start 返回的 level_url_full；没有则用 hls_url_full 把 index.m3u8 换成 level.json
     * @param playlistUrl hls_url_full（要读 #EXT-X-MEDIA-SEQUENCE）
     * @param fpsHint     level_fps，缺省 10
     * @param segHint     segment_sec，缺省 1.0
     */
    public LiveLevelMeter(String levelUrl, String playlistUrl, MediaPlayer player,
                          int fpsHint, float segHint) {
        this.levelUrl = levelUrl;
        this.playlistUrl = playlistUrl;
        this.player = player;
        this.fpsHint = fpsHint > 0 ? fpsHint : 10;
        this.segHint = segHint > 0 ? segHint : 1f;
        this.fps = this.fpsHint;
    }

    public void setListener(Listener l) {
        this.listener = l;
    }

    /** 在 MediaPlayer.start() 之后调用（越接近起播越好，anchor 依赖此刻的 MEDIA-SEQUENCE）。 */
    public void start() {
        if (running) return;
        running = true;
        io.execute(() -> {
            anchorMedia = playlistStartSec();
            while (running) {
                try {
                    step();
                } catch (Throwable ignored) {   // 轮询线程不能因为一次异常退出
                }
                try {
                    Thread.sleep(POLL_MS);
                } catch (InterruptedException e) {
                    return;
                }
            }
        });
    }

    public void stop() {
        running = false;
        io.shutdownNow();
        lastSeq = -1;
        lv = new float[0];
        post(0f);
    }

    // ------------------------------------------------------------------ 主循环

    private void step() {
        long now = System.currentTimeMillis();
        long pos = positionMs();

        // 播放器重载 / 用户拖动：位置回跳，用最新的播放列表重新锚定
        if (lastPosMs >= 0 && pos + SEEK_BACK_MS < lastPosMs) {
            anchorMedia = playlistStartSec();
        }
        lastPosMs = pos;

        JSONObject js = getJson(levelUrl);
        if (js == null) {
            post(0f);
            return;
        }

        int seq = js.optInt("seq", -1);
        if (seq != lastSeq) {                 // 只有新快照才算「还活着」
            lastSeq = seq;
            lastSeqAt = now;
            status = js.optString("status", "live");
            t0 = (float) js.optDouble("t0", 0);
            fps = (float) js.optDouble("fps", fpsHint);
            edge = (float) js.optDouble("edge", 0);
            JSONArray arr = js.optJSONArray("lv");
            float[] buf = new float[arr == null ? 0 : arr.length()];
            for (int i = 0; i < buf.length; i++) {
                buf[i] = (float) arr.optDouble(i, 0) / 100f;   // 服务端 0~100 → 客户端 0~1
            }
            lv = buf;
        }

        if ("ended".equals(status) || now - lastSeqAt > STALE_MS) {
            post(0f);
            return;
        }

        float mediaT = anchorMedia + pos / 1000f;
        if (mediaT > edge) mediaT = edge;     // 不查「还没写进流」的时间
        post(sample(mediaT));
    }

    /** 媒体时间 → 0~1；越界取首/尾格，格间线性插值。 */
    private float sample(float mediaT) {
        float[] a = lv;
        if (a.length == 0) return 0f;
        float x = (mediaT - t0) * fps;
        if (x <= 0f) return a[0];
        int i = (int) Math.floor(x);
        if (i >= a.length - 1) return a[a.length - 1];
        float k = x - i;
        return a[i] + (a[i + 1] - a[i]) * k;
    }

    // ------------------------------------------------------------------ 播放列表

    /**
     * 播放列表首片的媒体起始时间 = MEDIA-SEQUENCE × 单片时长。
     * 单片时长取窗口内最大的 #EXTINF：末片可能是被截断的短分片（实测 0.883 vs 0.998），
     * 用平均值会被它拉偏（46 片时偏 1.06 秒），用 TARGETDURATION 也会随分钟级通话累积漂移。
     */
    private float playlistStartSec() {
        String text = getText(playlistUrl);
        if (text == null) return anchorMedia;
        int seq = 0;
        float target = segHint;
        float unit = -1f;
        for (String raw : text.split("\n")) {
            String s = raw.trim();
            if (s.startsWith("#EXT-X-MEDIA-SEQUENCE:")) {
                seq = parseInt(s.substring(s.indexOf(':') + 1), 0);
            } else if (s.startsWith("#EXT-X-TARGETDURATION:")) {
                target = parseFloat(s.substring(s.indexOf(':') + 1), segHint);
            } else if (s.startsWith("#EXTINF:")) {
                String v = s.substring(8);
                int comma = v.indexOf(',');
                if (comma >= 0) v = v.substring(0, comma);
                float d = parseFloat(v.trim(), -1f);
                if (d > unit) unit = d;
            }
        }
        float step = unit > 0f ? unit : target;
        return seq * step;
    }

    // ------------------------------------------------------------------ 工具

    private long positionMs() {
        try {
            return Math.max(0L, player.getCurrentPosition());
        } catch (IllegalStateException e) {
            return 0L;
        }
    }

    private void post(float v) {
        Listener l = listener;
        if (l == null) return;
        main.post(() -> l.onLevel(v));
    }

    private JSONObject getJson(String url) {
        String text = getText(url);
        if (text == null) return null;
        try {
            return new JSONObject(text);
        } catch (Exception e) {
            return null;
        }
    }

    private String getText(String url) {
        HttpURLConnection c = null;
        try {
            c = (HttpURLConnection) new URL(url).openConnection();
            c.setConnectTimeout(3000);
            c.setReadTimeout(3000);
            c.setUseCaches(false);
            c.setRequestProperty("Cache-Control", "no-cache");
            if (c.getResponseCode() != HttpURLConnection.HTTP_OK) return null;
            try (InputStream in = c.getInputStream()) {
                ByteArrayOutputStream bos = new ByteArrayOutputStream();
                byte[] b = new byte[4096];
                int n;
                while ((n = in.read(b)) > 0) bos.write(b, 0, n);
                return bos.toString("UTF-8");
            }
        } catch (Exception e) {
            return null;
        } finally {
            if (c != null) c.disconnect();
        }
    }

    private static int parseInt(String s, int def) {
        try {
            return Integer.parseInt(s.trim());
        } catch (Exception e) {
            return def;
        }
    }

    private static float parseFloat(String s, float def) {
        try {
            return Float.parseFloat(s.trim());
        } catch (Exception e) {
            return def;
        }
    }
}
```

`micLevel01()` 仍是原来的 `AudioRecord` RMS 归一化值（0~1）。音量条取两者最大值：自己说话时跟麦克风，员工说话时跟 `level.json`，两边都静音时归零。

### 12.9.2 离线验算（实测会话 `lv_742062b5`）

| 输入 | 值 |
| --- | --- |
| 播放列表 | `#EXT-X-MEDIA-SEQUENCE:46`，`#EXT-X-TARGETDURATION:1`，5 片 `EXTINF` = 0.998456 ×4 + 0.883489（末片截断） |
| 首片起始媒体时间 | `46 × 0.998456 = 45.929 s`（若用 TARGETDURATION 得 46.0，偏 0.071 s；若用窗口均值 0.9755 得 44.871，偏 1.06 s） |
| `level.json` | `t0=0.0`、`fps=10`、508 格、`edge=50.8`、非零区间 22.8~47.5 s |

按 `mediaT = 45.929 + getCurrentPosition()/1000` 取格：

| 播放位置 | mediaT | 索引 | 电平（0~100） |
| --- | --- | --- | --- |
| 0.00 s | 45.929 | 459 | 53.2 |
| 1.00 s | 46.927 | 469 | 82.9 |
| 2.00 s | 47.929 | 479 | 0 |
| 4.87 s（窗口末尾） | 50.799 | 507 | 0 |

与 `level.json` 里非零区间 22.8~47.5 s 一致：起播时正处在语音尾部，播完 2 秒后进入静音段，没有出现「声音还在、条已归零」的错位。

**真机需要校准的一点**：Android `MediaPlayer` 对 HLS 的 `getCurrentPosition()` 是相对**本次播放起点**的；示例假设「0 = 起播时播放列表首片」，这也是绝大多数实现的默认行为，但不同厂商/版本可能有差异。建议第一次联调时打一行日志：

```java
Log.d("LiveLevel", "pos=" + mediaPlayer.getCurrentPosition()
        + " seq=" + lastSeq + " t0=" + t0 + " edge=" + edge);
```

若发现 `pos` 增长而 `mediaT` 明显落后/超前于 `edge`，只需把 `anchorMedia` 的取值改成「首次 `pos > 0` 时的 `seq`」即可，其余采样逻辑不用动。
